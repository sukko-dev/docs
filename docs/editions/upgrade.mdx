# Licensing & Upgrades

Every edition of Sukko requires a license key, **Community included** — each service refuses to start without one. Community keys are **free**, issued per account; Pro and Enterprise are purchased. Setting or changing a key is a single environment-variable change — no data migration, no downtime.

:::info Time to complete
~2 minutes
:::

## Step 1: Get a License Key

### Community (free)

1. Create an account at [sukko.dev](https://sukko.dev) and verify your email address.
2. Your free Community key is shown on your [dashboard](https://sukko.dev/dashboard) — copy it.

### Pro or Enterprise

Purchase a Pro or Enterprise plan from the [pricing page](https://sukko.dev/pricing). The key appears on your dashboard the same way.

Keys are signed JWTs and look like:

```
eyJlZGl0aW9uIjoiY29tbXVuaXR5Iiwi...
```

## Step 2: Set the License Key

Set the key on every service (gateway, server, provisioning).

### Docker Compose (sukko CLI)

```bash
sukko license set eyJlZGl0aW9uIjoi...
sukko down && sukko up
```

### Kubernetes (Helm)

Create a secret holding the key, then point the chart at it:

```bash
kubectl create secret generic sukko-license \
  -n sukko \
  --from-literal=license-key=eyJlZGl0aW9uIjoi...

helm upgrade sukko ./deployments/helm/sukko \
  -f my-values.yaml \
  -n sukko \
  --set global.license.existingSecret=sukko-license
```

The chart reads the key from the secret's `license-key` entry (override with `global.license.existingSecretKey`).

### Environment Variable (Direct)

```bash
export SUKKO_LICENSE_KEY="eyJlZGl0aW9uIjoi..."
```

## Step 3: Verify

Check the edition endpoint on any service:

```bash
curl http://localhost:8080/edition | jq .
```

Expected output (Pro shown):

```json
{
  "edition": "pro",
  "limits": {
    "max_tenants": 50,
    "max_total_connections": 10000,
    "max_shards": 8,
    "max_topics_per_tenant": 50,
    "max_routing_rules_per_tenant": 100
  }
}
```

Or via the CLI:

```bash
sukko edition
```

## Changing Editions

An **upgrade or renewal** takes effect immediately via hot-reload. A **downgrade** — a lower edition, or a smaller Pro capacity band — is accepted and persisted but takes effect only at the **next restart**; a running deployment is never downgraded or stopped while it is serving.

To move to a lower edition (including back to **Community**), set that edition's key and restart — you cannot run without a key:

```bash
sukko license set <lower-edition-key>
sukko down && sukko up
```

Existing tenants and data are preserved. If you exceed Community limits, new tenant/connection creation is rejected until you are within limits. See [Edition Lifecycle](./lifecycle) for the full upgrade, downgrade, and expiry behavior.
